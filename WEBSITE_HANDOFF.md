## Backup and publishing routine

1. Keep the complete website in a private GitHub repository.
2. Make changes in a separate branch when the change is large.
3. Review the change on the private website.
4. Merge only an approved version into the main branch.
5. Publish the approved version.
6. Keep a downloadable ZIP backup after major milestones.

## Maintenance rhythm

### Monthly, about 20 minutes

- Test navigation and buttons.
- Submit a test inquiry.
- Check the site on a phone and computer.
- Confirm all images load.

### Quarterly, about 60 to 90 minutes

- Replace weaker portfolio work with stronger recent work.
- Review wording, services, and claims for accuracy.
- Review analytics and search performance.
- Check accessibility, loading speed, and domain renewal status.

### Before every major event season

- Confirm packages, availability, response times, and inquiry questions.
- Update the featured work and testimonials.
- Create a full backup before major edits.
